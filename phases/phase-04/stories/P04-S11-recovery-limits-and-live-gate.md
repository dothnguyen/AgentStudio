# P04-S11 — Recovery, limits and live gate

Status: Done (2026-10-24), except the real-provider live gate (step 5), which is prepared but must be run by the operator — see Evidence
Depends on: P04-S10 (scheduler and run-board)
Architecture: [P04 design contract](../README.md#design-contract), §E

## Goal
The generic board survives crashes and provider usage limits, the recovery is documented and drilled, and a real run on a real project closes the phase.

## Implement in this order
1. Lease expiry and crash recovery: a coordinator or runner death releases the claim and the ticket returns to its rule's status exactly once; orphan worktrees are reconciled; `ticket retry` clears a stuck claim.
2. Usage limits: a `USAGE_LIMIT` result releases the ticket without counting a round and marks the member `limit_reached`; `board resume --member M` makes it eligible again (extending the agents-only `board.resume` S06 kept, design contract §F; `--agent` / `--all` keep working).
3. RECOVERY.md section for the new board (`You see | Meaning | Command`) covering each code and a danger-zones subsection, with a doc test that every code is documented.
4. Drill script on the fake provider (coordinator killed, runner killed, merge conflict, round limit, usage limit, stuck claim), run in isolated state dirs, writing evidence.
5. Live gate: with real providers on a throwaway repo, three tickets in a new phase made current with `board phase set-current`, one dependency, one forced QA fail, all `done`; a ticket in another phase is left alone; also confirm the other team stays free for `ask`. Record the run folder. Update ROADMAP/PRD only if the operator asks.

## Evidence

- **Lease expiry and crash recovery** (`boardsched._recover`, first thing in every tick): a claim whose `lease_until` passed while its run is unsettled (queued, running or paused — coordinator or runner death) is released **exactly once** (the release clears the claim, so the next pass finds nothing), its run cancelled, the ticket returned to its rule's `when.status`, with `ticket.claim_released` + `ticket.lease_expired` events and `run_id` recorded so a late report of the cancelled run is never re-applied. Orphan worktrees (registered under the workspace's worktree root but referenced by no ticket row, e.g. a crash between merge commit and cleanup) are removed. The tick now auto-applies only `succeeded`/`failed`/`cancelled` runs; a **paused** run waits for the operator (assignment resolve) or the lease. **`ticket retry KEY`** (dispatch `ticket.retry`, CLI `ticket retry`) clears a stuck claim by hand: release + cancel + `ticket.released` event; `TICKET_TRANSITION_INVALID` on a ticket that is not claimed.
- **Usage limits:** the tick detects a failed run whose assignment carries `USAGE_LIMIT` (report_rules has already marked the member `limit_reached` from the real report) and releases the ticket **without counting a round** (no `rounds` change, `run_id` recorded, `ticket.claim_released` reason `usage_limit`). **`board resume --member M`** (S06's agents-only `board.resume` extended per §F): the dispatch validator takes exactly one of `--agent` / `--member` / `--all`; the coordinator resolves the member by `member_id` or display name (case-insensitive) in the running workspace team (`MEMBER_NOT_FOUND` otherwise); `--agent`/`--all` keep working.
- **Applier fix found by the drills:** a round-limit block recorded the ticket's *during* status as its return status, so `ticket unblock` landed tickets where no rule worked them. Blocked tickets now return to the rule's `when.status`.
- **RECOVERY.md:** a "The generic board (P04)" section (You see | Meaning | Command) covering every board code — `BOARD_CONFIG_INVALID`, `BOARD_ALREADY_RUNNING`, `BOARD_STATUS_UNKNOWN`, `BOARD_RULE_MISSING`, `PHASE_*`, `TICKET_*`, `WORKTREE_*`, `TEAM_NOT_RUNNING` — plus the lease/usage-limit/stuck-claim/merge-hold/MERGE_CONFLICT behaviours and a danger-zones subsection (main checkout, worktrees location, `leaseSeconds` vs run duration, current-phase changes, merge abort). The unit doc test derives the code list from `protocol.py` (every `BOARD_*`/`PHASE_*`/`TICKET_*`/`WORKTREE_*` constant) and fails if any is missing; the dead P03 constant `TICKET_DEPS_NOT_MERGED` was removed.
- **Drills** (`tests/integration/test_p04_s11_drills.py`, one method per drill, each in its own Sandbox = isolated state dir and tmux server, fake provider): **coordinator killed** (SIGKILL mid-run; the runner reports into the inbox, the restarted coordinator applies the report once and the ticket reaches `done` with exactly one `ticket.outcome_applied`); **runner killed** (SIGKILL the runner pid; the lease expires, the claim released exactly once, the run cancelled, the ticket re-claimed and finished); **merge conflict** (two workers, two isolated worktrees cut from the same base; the first merge lands, the second returns to `onFail` with `MERGE_CONFLICT` and the base untouched); **round limit** (a strict workflow whose validation stage always fails; two failed rounds → `blocked` with `ROUND_LIMIT:build` and `rounds {build: 2}`; `ticket unblock` returns it to `build`); **usage limit** (the fake's usage_limit outcome replayed at the database level; the ticket is released without a round, `board resume --member Ryan` makes it eligible, the board finishes it); **stuck claim** (`ticket retry` releases the claim, cancels the run, the ticket finishes on the next claim).
- **Live gate:** `scripts/live/board_live_gate.py run [--providers codex,claude]` (refuses the fake provider) drives the step-5 scenario on real providers — rules check, two teams in two throwaway workspaces, `board phase add sprint-2` + `set-current`, three tickets in it (one depending on another with `requiresDeps`, one whose body forces a failed first review), all to `done`, the other-phase ticket untouched after `stop-board`, and an `ask` answered by the other team while the board runs — writing an evidence bundle with per-ticket timelines under `<state>/board-live-gate/<time>/`. Its `--dry-run` (fake provider, clearly marked "plumbing proof, not live-gate evidence") passes every step in an isolated state dir (verified manually and by `tests/integration/test_p04_s11_gate_dryrun.py`). **The real-provider run could not be executed in this session — no authenticated providers are available here (the pre-existing `RealCodexBinary` probe failures on the untouched baseline are the same cause). Run `python3 scripts/live/board_live_gate.py run` from WSL with codex/claude signed in and record the run folder here; ROADMAP/PRD stay unchanged until then, per step 5.**
