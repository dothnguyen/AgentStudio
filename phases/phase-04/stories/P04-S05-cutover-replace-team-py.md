# P04-S05 — Cut-over: the new team replaces team.py

Status: Done (2026-10-24)
Depends on: P04-S04 (ask and one-off workflows)
Architecture: [P04 design contract](../README.md#design-contract), §B, §C "Story delivery (S05)", constraints 1-2 and 4

## Goal
Every `team.py` command the operator uses to deliver a story exists as `agent-studio team ...` with the same behaviour and the same per-story state files, so a story begun with `team.py` can continue with the new commands. The new commands are verified on this story itself (the operator runs `qa`, `final` and `commit` of S05 with them) and on S06, which is delivered end to end with them. `team.py` is **not** deleted here: deleting it means deleting the unit tests that import it, which constraint 4 allows only in S06, so the deletion of `team.py` and the CLI-side `team.json` fallback is the last step of [P04-S06](./P04-S06-remove-software-board.md) after S06 has itself been delivered with the new commands (constraint 2).

Behaviour to keep, per command (the reference is `scripts/team/team.py` at the commit this story starts from; task texts are copied verbatim):
- `unpack BRIEF --out DIR`: one `task.direct` with `workspace_write` to the ProductOwner member (else the TeamLead member) with the `c_unpack` text (the `tickets.json` sentence only for ProductOwner). No state file.
- `review STORY`: TeamLead, `workspace_write`, the `c_review` text; parse the verdict (last JSON line, as `verdict()`); save `story`, `approved`, `review`; list files the lead changed (git status before/after); warn about files outside `phases/`, `PRD.md`, `ROADMAP.md`; ask `Commit the planning changes now? [Y/n]` and commit only the planning files with `Review <story file name>: story updated by the team lead`.
- `dev STORY [--force]`: refuse unless `approved` (or `--force`) and unless the git tree is clean; save `base` = `HEAD`; start the P00 workflow (Developer member as developer, QA member as reviewer) with the `c_dev` text and wait; save `story`, `base`, `workflow`, `findings` (last verdict findings), `qaPassed` (= workflow `succeeded`); print the last test run.
- `fix STORY [--integration]`: refuse without `base`; run validation (below); Developer, `workspace_write`, `c_fix` text with the non-`SUGGESTION` findings and the test output. No state change.
- `qa STORY [--integration]`: refuse without `base`; run validation; QA, `read_only`, `c_qa` text with VALIDATION and the changes section (`git diff` since `base`, size limits as `changes_section`); save `findings` (or `["unit tests fail - see the test output"]`) and `qaPassed` = tests pass and verdict pass.
- `final STORY [--force] [--integration]`: refuse unless `qaPassed` (or `--force`); run validation; TeamLead, `workspace_write`, `c_final` text; save `finalPassed`, `commitMessage` (the ```` ```commit ```` block or null), `finalReview`; on fail also save `findings` and `qaPassed: false`.
- `commit STORY [--skip-integration]`: refuse unless `finalPassed`; integration gate `python3 scripts/validate.py --touched` (skipped with `--skip-integration`); show `git status --short` and the message (default `Implement <story file name>`); ask `Commit all of the above with this message? [y/N]`; `git add -A`, `git commit -F -`; save `committed` = new `HEAD`.
- Validation for `fix` / `qa` / `final`: argv from `.agent-studio/workflow.json` `validation.argv` with `--touched` / `--all` replaced by `--unit` unless `--integration` (as `validation_argv`), timeout `validation.timeoutMs` (default 180000), last 5 KiB of output.
- `run-workflow NAME --story PATH`: the `run_prompt` story text, clean-tree check, `base` = `HEAD`, then S04's `run-workflow` with `--wait` implied; after it finishes save `story`, `base`, `workflow`, `findings`, `qaPassed`, `finalPassed`, `commitMessage` exactly as `c_run` (commit message only from a stage whose outcome is `verdict_pass`).
- `index`: `ctags` with the same arguments and output file `.agent-studio/cache/tags`; `ctags` missing is an error naming `sudo apt install universal-ctags`.

## Implement in this order
1. Check the inventory and the behaviour list above against `scripts/team/team.py`; if `team.py` does something the list misses, add it to the list in this file (no new behaviour).
2. **Module.** New `backend/agent_studio/storycli.py`, called from `cli._local_command` for `team unpack | review | dev | fix | qa | final | commit | index`; `team run-workflow --story` is added to `teamcli.py` and calls into `storycli` for the state part. These commands run in the CLI process (operator-side glue, like `team.py`): they run `git`, the validation command and `ctags` themselves and reach agents only through the existing dispatch commands (`team.status`, `task.direct` + `watch.follow`, `workflow.start` + `watch.follow_workflow`), reusing `teamcli`'s team resolution (`--team`, `--workspace`, `TEAM_NOT_RUNNING`) and member matcher. No dispatch, coordinator or engine change.
3. **Role → member.** Each command picks the member by role from `team.status` `data.members` (role compared case-insensitively): exactly one → that member; none → `ROLE_UNBOUND`; several → `ROLE_AMBIGUOUS` with remediation `pass --member <name>` listing the candidates. `unpack`, `review`, `fix`, `qa`, `final` take `--member REF` (S04 `find_agent` rules) to override the pick; `dev` binds Developer and QA this way (no override; use `run-workflow --bind` for other bindings). Nothing is written to the inbox when the pick fails.
4. **State files.** Same directory and format as `team.py`: `$XDG_STATE_HOME` (default `~/.local/state`) `/agent-studio/project-team/<slug>/story-<key>.json`, where `<slug>` is `re.sub(r"[^A-Za-z0-9]+", "_", WS).strip("_")` and `WS` is the workspace root path (the resolved workspace; for a git checkout this must equal `git rev-parse --show-toplevel`, which is what `team.py` used), and `<key>` is `team.py`'s `story_key`. Read the existing file, update only the keys listed above, keep every other key, write JSON with two-space indentation (atomic replace). The `team.json` state file (`team.py`'s saved team ids) is neither read nor written; the team comes from the definition (§C).
5. **Texts and output.** Task texts are byte-identical to `team.py` (clipped to 30 KiB as `clip`); the agent output is shown under the same `===== title =====` headings; next-step hints name `agent-studio team <cmd> <story>` instead of `team.py <cmd>`. A coordinator `AGENT_BUSY` whose message mentions `waiting_input` adds the hint `agent-studio team blocked` / `team resolve --member <name> --action fail`.
6. **Errors** (§B human form, exit 1): story file missing → `BAD_REQUEST` "Story file not found in the workspace: <path>"; a refused step (not approved, no development recorded, QA not passed, final not approved) → `STORY_NOT_READY` with remediation naming the command to run first (or `--force` where `team.py` allows it); dirty tree at `dev` / `run-workflow --story` → `WORKSPACE_DIRTY`; integration gate failed → `TESTS_FAILED` (remediation `agent-studio team fix <story>`, or `--skip-integration`); commit declined → `NOT_COMMITTED`; `ctags` missing → `BAD_REQUEST`.
7. **`--json`.** Prints the envelope `{"ok": true, "data": {"story", "key", "state", "status", "output"}}` (`state` = the saved state record, `status` = the agent's assignment or workflow status, `output` = the agent text; `index` gives `{"symbols": N, "path"}`). With `--json` nothing prompts: `review` does not commit planning changes and returns `data.editedFiles`; `commit --json` is `BAD_REQUEST` "commit asks for confirmation; run it without --json".
8. **`team attach --team ID`** also accepts a definition id (resolved like `team stop`, S03); a runtime UUID works as before.
9. Add every new command and flag to `USAGE`. Neither `storycli.py` nor the changed part of `teamcli.py` imports `board`, `board_scheduler`, `board_config`, `tickets`, `bugfile` or `manifest`, and none sends a `board.*` or `ticket.*` command.
10. **Parity tests** (`tests/unit/test_p04_s05_parity.py`): load `scripts/team/team.py` as the existing unit tests do (`AGENT_STUDIO=/bin/true`, `spec_from_file_location`), stub its `cli`, `sh`, `subprocess.run`, `input` and `STATE`, stub the new commands' dispatch calls, git and validation the same way, and run one fixture story (`tests/fixtures/p04_s05/` with a story file and seeded agent answers: verdict pass and fail, a ```` ```commit ```` block) through `review → dev → qa (fail) → fix → qa (pass) → final → commit` and `run --story`, in both. Compare per step: the dispatch command and args (team.py's `cli(...)` argv turned into a request with `cli._human_request`, ignoring idempotency keys and timeouts), the task text, the validation argv, the git commands and the state file JSON. Agent ids differ only through the role mapping (the fixture maps role → same agent id in both). These tests are deleted with `team.py` in S06.
11. **Continuation test:** a state file written by `team.py` (`review` + `dev`) is read by the new `qa` / `final` / `commit`, and the file written back has the same keys and values `team.py` would write.
12. **Operator step (not automatable, after QA of this story passes):** `agent-studio team import-legacy` (this repo has only `.agent-studio/team.json`), `agent-studio team start`, then run `agent-studio team qa`, `team final` and `team commit` for this story, continuing the state `team.py` left. The commands and their result go into Evidence (the final review records `qa` and `final`; `commit` is the step after it). If a new command fails here, the operator finishes the story with `team.py` and the failure is a finding for the developer.
