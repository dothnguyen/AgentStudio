# P04-S10 — Scheduler and team run-board

Status: Done (2026-10-24)
Depends on: P04-S08 (phases), P04-S09 (rules, outcome applier)
Architecture: [P04 design contract](../README.md#design-contract), §E

## Goal
`team run-board` binds a team to the board and starts the scheduler; `stop-board` stops claiming while running work finishes. The scheduler claims tickets by rule, phase, dependencies, caps and free members, with optional worktree isolation and a coordinator-only `merge` action.

## Implement in this order
1. Binding: one team runs the board at a time (`BOARD_ALREADY_RUNNING`). `run-board --team T` runs `rules check` first; `stop-board` stops claiming and leaves running work alone.
2. Tick: for each rule in priority order, pick tickets in that status that are `ticket_in_scope` (their phase is the effective current phase: the pointer, or the default phase when none is set), have dependencies in a `done` status when `requiresDeps`, are under the rule's `cap`, and match a free member of the rule's role. Claim with a lease, set the `during` status if configured, and start the rule's workflow.
3. Free-member rule: members running `ask`/`run-workflow` or another ticket are never claimed; `ask` to a member holding a ticket returns `AGENT_BUSY`.
4. Workspace modes: `main` (default), `none`, and `worktree` (one branch and worktree per ticket using the retained `worktrees.py`/`gitws.py`). `task.direct` / `workflow.start` then accept a worktree again only when it is registered to a live ticket of the generic board (restoring the check S06 removed, design contract §F); every other path stays `WORKTREE_NOT_REGISTERED`.
5. `merge` action: the coordinator, with no agent, merges the ticket branch into the base branch under a main-checkout lock; a conflict sends the ticket to `onFail` with findings, never leaves the checkout dirty.
6. Finished runs go through the S09 applier.

## Done when
- [x] The phase filter (tickets of other phases are never claimed; with no current phase the default phase is worked; changing the current phase mid-run lets running work finish and uses the new phase for new claims), `requiresDeps`, and per-rule `cap` are respected. Test: unit tick tests.
- [x] A ticket runs through three rules to `done` on the fake provider with no operator command beyond `run-board`. Test: integration.
- [x] A busy member is never claimed and `stop-board` stops new claims only. Test: integration.
- [x] Worktree mode isolates two tickets, and `merge` lands both, including a conflict that returns to `onFail`. Test: integration on a throwaway repo.

## Evidence

- **Migration 13** (`schema.MIGRATION_13`, `SCHEMA_VERSION = 13`): `board_state` gains the binding (`team_id`, `run_status` running/stopped, default stopped) and `tickets` gains `active_run_id` (the run a ticket currently holds) and the worktree columns `branch`/`worktree_path`. Migrations 1–12 unedited. New code `BOARD_ALREADY_RUNNING`.
- **Binding.** `team run-board [--team T]` (teamcli) → dispatch `board.run {workspace, teamId}` → `boardsched.bind_team`: runs `rules check` first (`BOARD_CONFIG_INVALID` with the problem list otherwise), requires the team running on that workspace, refuses a second running team (`BOARD_ALREADY_RUNNING`, rebinding allowed once stopped), and marks the board running. `team stop-board` → `board.stop` sets `run_status='stopped'`. `board.json` gains optional top-level `leaseSeconds` (default 120) and `baseBranch` (default `main`); `rules check` now also proves every workflow uses its rule's role and that `action` values are known (`merge`).
- **Tick** (`boardsched.tick`, called from the coordinator loop after `workflow.advance`; never raises — per-workspace errors are recorded in its return value). Per bound workspace, in two transactions: (1) always — apply finished runs through the S09 applier (also while the board is stopped: running work finishes) and perform coordinator-only merge actions; (2) only while running — claim. Claiming: rules in `priority` order (then config order); candidates in the rule's `when.status` with no assignee, in `ticket_in_scope` (the effective current phase), with all dependencies in a finished status when `requiresDeps`, `cap` counted as tickets the rule holds, and a free member of the rule's role (idle, alive pane, no active assignment, holding no ticket — so a member running `ask`, `run-workflow` or another ticket is never claimed, and `ask` to a member holding a ticket is `AGENT_BUSY` through the engine's own busy rules). The claim (lease, `during` status when configured, `ticket.claimed` event) is written before the start so the worktree registration exists; a failed start releases the claim back to the `when.status` with a `ticket.claim_released` event.
- **Workspace modes.** `main` (default) holds while the checkout is dirty or mutating work runs; `none` behaves like `main` for the engine; `worktree` creates one branch+worktree per ticket via the retained `worktrees.py` (`ticket/T-<key>-<slug>` off `baseBranch`, reused on retry rounds) and starts the run in it. `task.direct`/`workflow.start` accept a worktree again **only** while it is registered to a claimed ticket of the board (`boardmodel.registered_worktree` from `tasks.run_workspace`; §F restored, S06 unit tests still green, new `WorktreeRegistration` unit test).
- **Merge action.** `boardsched._run_merge_actions`: for `action: "merge"` rules, tickets in `when.status` with a branch; the tick is single-threaded so one merge at a time holds the main checkout (dirty / wrong branch / mutating work holds the ticket with a `ticket.merge_held` event instead). Squash-merge into `baseBranch`, commit `<key>: <title>`, move to `onPass`, remove the worktree (kept on conflict); a conflict aborts with `reset --merge` (never leaves the checkout dirty) and sends the ticket to `onFail` with a `ticket.merge_conflict` event naming `MERGE_CONFLICT: <files>`. An already-merged branch passes through.
- **Outcome application.** The tick applies finished `active_run_id` runs via the S09 applier with the claiming rule (found by the `during` status), which releases the claim (`assignee`/`lease`/`active_run_id` cleared) and records `run_id` for idempotency.
