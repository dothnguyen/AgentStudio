# P03-S11 — Usage limits: classification, `limit_reached`, `board.resume`

Status: Done (2026-10-23)
Depends on: P03-S06
Architecture: [P03 design contract](../README.md#design-contract), §H (usage limits); brief §6b

## Goal

When a provider says its usage or rate limit is reached, the adapter reports `USAGE_LIMIT` (with the reset time if given) instead of a generic error. The board then cancels that run, puts the ticket back in its column without counting a round, and marks only that agent `limit_reached`, so it is offered no work until the operator runs `board.resume`. Other agents and columns keep working.

How it flows today (so nothing new is invented): a `failed` final report moves the agent `busy → idle` (`report_rules.FINAL_MAP`), the P01 engine then pauses the run with the assignment's `diagnosticCode` (`workflow._pause`), and the S06 applier blocks the ticket as `RUN_PAUSED:<code>`. This story changes the agent step and the applier step for the code `USAGE_LIMIT` only.

## Implement in this order

1. **Report field.** `providers/base.py`: `ParseState.terminal` may carry `limitResetAt`; `finalize` copies it to an optional report key `limitResetAt` (UTC `YYYY-MM-DDTHH:MM:SSZ`, or absent/null). `USAGE_LIMIT` is a terminal `code` like `AUTH_REQUIRED` (`status` `failed`). `contract.validate_report`: `limitResetAt`, when present and not null, must be a string matching that format, else `BAD_REPORT`.
2. **Fake scenarios.** `fake_cli.py` scenarios `usage_limit` (emits a `result` with `status: "error"`, `code: "usage_limit"`, `resetAt: "2030-01-01T15:00:00Z"`, exit 1) and `usage_limit_no_reset` (the same without `resetAt`). The fake adapter maps `code: "usage_limit"` to `USAGE_LIMIT` (+ `limitResetAt` from `resetAt`); any other error stays `PROVIDER_ERROR`. Add both to the fake `CONTRACT.md` scenario list.
3. **Claude classifier.** In the `result` branch of the Claude adapter, a non-success result whose text matches the limit pattern → code `USAGE_LIMIT`, with the reset time converted to UTC ISO when the text carries one (epoch seconds or a clock time with zone); otherwise `limitResetAt` absent. Fixtures go beside the existing ones as stream-json lines: `tests/fixtures/claude/usage_limit*.jsonl`, captured from the real CLI either from a real occurrence or by pointing it at `tests/fixtures/claude/fake_anthropic_api.py` scripted to answer with the provider's documented rate-limit / usage-limit error (the same method as the other fixtures). **Exception, decided by the operator:** where neither a real occurrence nor a working stand-in capture is available to the implementer (the sandboxed agent cannot run the real CLI or open ports), hand-written fixtures modelled on the documented message are accepted, provided the README and CONTRACT say plainly that they are not captures and list the replacement as a TODO. Each fixture's source (real occurrence, stand-in API + the documentation URL/quote, or `hand-written` with that TODO) is recorded in `tests/fixtures/claude/README.md` and summarised in `providers/claude/CONTRACT.md`. The existing `tests/fixtures/claude/api_error.jsonl` is the ordinary-error control. **Codex:** there is no captured limit sample (`tests/fixtures/codex/` has only `captured-0.163.0-network-unreachable.jsonl`), so its classifier is not added; record that gap in `providers/codex/CONTRACT.md` (unrecognised → `PROVIDER_ERROR`, never guessed).
4. **Schema v8.** `schema.AGENT_STATES` gains `limit_reached`; agent transitions gain `busy → limit_reached`, `waiting_input → limit_reached`, `limit_reached → idle | offline | error` (team stop and dead-pane marking keep working on a limited agent). `state.MIGRATIONS[8]` rebuilds `agents` with the new CHECK and a nullable `limit_reset_at TEXT`, copying every existing column (the P01 §F rebuild pattern: `foreign_keys` off for the rebuild, then `PRAGMA foreign_key_check`), `SCHEMA_VERSION = 8`. Startup reconcile leaves `limit_reached` agents alone (it only resets `busy`/`waiting_input`), so the flag survives a coordinator restart.
5. **Agent step (P00 report application).** In `report_rules` (final report): status `failed` with `diagnosticCode == "USAGE_LIMIT"` moves the agent to `limit_reached` (not `idle`), sets `limit_reset_at` from the report, and writes `board.limit_reached {agentId, resetAt}` (`resetAt` null when unknown) in the same transaction. This applies to direct tasks too.
6. **Board step (S06 applier).** In `board._apply`: a `paused` run whose `_paused_code` is `USAGE_LIMIT`, while the ticket is still in its working status, is not blocked. The applier cancels the run (the `workflow.cancel` path, actor coordinator), moves the ticket back to `_queue(tx, ticket)` with `ticket.released {reason: "usage_limit"}`, clears assignee and lease, counts no round, leaves `findings_json` unchanged, and sets `applied_run_id` (one application, idempotent). Every other paused code keeps the S06 `RUN_PAUSED` row.
7. **Dispatch refuses a limited agent.** `tasks` dispatch already refuses any non-idle agent with `AGENT_UNAVAILABLE` (only `busy`/`waiting_input` give `AGENT_BUSY`); keep that. Add `limit_reached` to the refused availabilities of the `workflow.start` binding check (`workflow.py`, currently `offline`/`error`) and of the `assignment.resolve` retry check (`resolve.py`), both `AGENT_UNAVAILABLE`. `ticket.start` inherits it from `workflow.start` and rolls back its claim (S05 rule).
8. **`board.resume`.** Args `{workspace, agentId?, all?}`: exactly one of `agentId` or `all: true`, else `BAD_REQUEST`. Scope is the running team on the canonical workspace (none → `TEAM_NOT_RUNNING`); an `agentId` outside it → `AGENT_NOT_IN_TEAM`, unknown → `NOT_FOUND`. Each named agent that is `limit_reached` → `idle`, `limit_reset_at` cleared; agents in any other state are skipped, not an error. One `board.resumed {agentIds}` event when at least one agent was resumed. Receipt `{resumed: [agentIds]}`. Mutating (idempotency key, command inbox), same JSON from the CLI `agent-studio board resume --workspace W (--agent ID | --all)` and `serve`.
9. **Visibility.** The `snapshot` agent rows carry `availability: "limit_reached"` and the reset time (the serialized `limit_reset_at`). `scripts/team/team.py status` prints, per limited agent, `LIMIT: <display name> (<provider>) until <limitResetAt>` (`until unknown` when null) after the agent lines.
